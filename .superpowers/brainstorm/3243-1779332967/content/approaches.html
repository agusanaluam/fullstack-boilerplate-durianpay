3 Architecture Approaches

Pick the overall architecture for the payment dashboard

A

Pinia + SQLite — Recommended

Vue 3 Pinia for state, payments seeded in SQLite (same DB as users). Clean layered Go backend following existing handler/usecase/repo pattern. Docker Compose wraps both services.

Pros

  • Data persists across restarts
  • Matches existing codebase pattern
  • Production-realistic

Cons

  • Slightly more backend work (SQL seed + repo)
B

Pinia + In-Memory

Payments stored in a Go slice (no DB migration). Seed data hardcoded at startup. Frontend identical to Option A.

Pros

  • Fastest backend implementation
  • Zero DB schema changes

Cons

  • Data resets on restart
  • Less impressive to reviewers
C

Pinia + SQLite + Vue Query

Same as A but adds TanStack Vue Query for server state (caching, background refetch, loading states). More complex setup.

Pros

  • Best server-state UX (auto-refetch, stale-while-revalidate)
  • Shows advanced frontend knowledge

Cons

  • Extra dependency, more complex
  • Overkill for a dashboard with no real-time data
